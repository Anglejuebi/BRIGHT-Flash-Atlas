05 证据台账

这些数字支持什么。

四条主张，每条都附证据与边界。页面的目标是让比较可读，而不是隐藏竞争。

竞争语境

怎样让结论更稳健。
  • 让 Pipeline 使用 ep6 Student，或让 1007 使用 ep3，从而把架构比较变成同 checkpoint 消融。
  • 实测 1007 自己的时延与阶段拆分；当前 2.08 s / 4.51 s 为沿用值。
  • 同时报告两个模型的 held-out 测试均值，并给出 bootstrap 置信区间，而不是混用验证集与测试集列。
方法与数据来源 引用前请阅读

任务集

20 任务主表取我们的模型评估与基线表的交集。17 任务敏感性视图移除 NAT-ALL、NAT-HR+ 与 NAT-TNBC。 基线模型有 26 项任务；我们的模型未覆盖 DFS、OS、 BRACS、NIT 或 PD-L1，因此这些任务在所有比较中均被排除。

指标

Macro one-vs-rest AUC。1007 的表内取值为 best_validation.macro_ovr_auc；其 held-out 测试均值在注意事项中单独列出。 源表中的基线 AUC 带 95% 置信区间；我们的模型行没有。

计时

“仅模型”指单张切片的模型流水线：特征 I/O + 计算（Pipeline 另含 S2 路由）。 “端到端”再加入共享的 2.43 s 预处理（其中分割 1.33 s）。计时来自 150 张切片的基准。 1007 是声明式共享 profile，不是新跑的结果。

权重与显存

权重为 model_paths.py 中登记文件的体积。峰值显存在 batch 1 下逐模型测量。 1007 的 ep6 checkpoint 不在工作区；这里用 ep3 Student 文件作同架构代理。
